# Glance backend

Node.js + TypeScript backend for **Glance — Telegram Digest & Drafts on G2**
(Even Realities, Track 01). Polls the Telegram test channel, builds a digest
with a local-LLM summary + reply draft, and relays replies through the bot.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/` | API index |
| `GET` | `/health` | Liveness + last poll status |
| `GET` | `/digest` | Digest items (one per chat): title, summary, draft, unread |
| `GET` | `/digest/:id` | Detail: last 20 messages + summary + AI draft |
| `POST` | `/reply` | `{itemId, text}` → `sendMessage` via the bot |
| `POST` | `/stt` | 501 — not implemented yet (day 3) |

## Run

```bash
npm install
npm run build
npm start          # listens on http://127.0.0.1:3000
```

Env: `PORT` (default 3000), `POLL_MS` (default 15000),
`OLLAMA_HOST` (default `http://127.0.0.1:11434`),
`OLLAMA_MODEL` (default `qwen2.5:3b`), `DATA_DIR` (default `backend/data`).

## How Telegram is reached (no token in this repo)

The bot token is **never** stored here — not in code, env files, logs, or
commits. Bot API calls (`getUpdates`, `sendMessage`) are delegated to the
registered connector helper
`~/workspace/custom-connectors/custom.telegram-bot/bin/telegram-bot.py`,
which holds the credential in Muse's secure store and swaps it into the
request path. This backend only spawns that helper and parses its JSON.

## Summaries

`GET /digest` summaries and reply drafts are generated by local Ollama
(`qwen2.5:3b`); when Ollama is unavailable or slow, the backend falls back
to an extractive summary (first messages, truncated) so the endpoints keep
working. No paid API, no API key.

## Data

Polled messages and digest state live in `backend/data/state.json`
(gitignored — live channel content, local only).
